# Инструкция для Claude (читать в начале КАЖДОЙ сессии)

Проект: новая платформа туроператора «Русь» (rtoperator.ru) — витрина + кабинеты + ядро заказов.
Пишем с нуля. Вся техническая часть — на Claude. Пользователь даёт команды, доступы, тестирует, принимает решения.

## Порядок работы
1. Прочитай `docs/README.md` → `docs/CONTEXT.md` → `docs/MAP.md`.
2. Перед работой над функционалом прочитай `docs/features/<ID>/context.md` и `tech.md` этого функционала
   и context.md всех функционалов, указанных в его связях.
3. Не противоречь `docs/DECISIONS.md`. Если решение нужно поменять — спроси пользователя, потом обнови файл.
4. Не начинай разработку без команды пользователя «начинай» (на 2026-10-19 команды ещё не было).

## Правило документации (обязательно, это просьба пользователя)
Любое изменение функционала = в том же коммите обнови:
- `context.md` — связи (реальные и возможные), важность, наблюдения, риски;
- `tech.md` — как устроено технически (сущности, правила, API, где в коде, тесты);
- `user.md` — как этим пользоваться (для туриста / менеджера / агента / админа).
Новые решения → `docs/DECISIONS.md`, новые вопросы → `docs/OPEN-QUESTIONS.md`,
отложенное → `docs/BACKLOG.md`, новые связи → `docs/MAP.md`.
Пиши в context.md то, как ты реально понимаешь функционал, включая сомнения.

## Ограничения среды
- Нет SSH из среды разработки, только HTTPS через прокси → деплой через GitHub Actions, инфраструктура через Terraform/API облака.
- Секреты никогда не просим в чат и не коммитим: GitHub Secrets (деплой/прод) или настройки окружения сессии (разработка).
- Контейнер временный: всё ценное — коммитить и пушить.
