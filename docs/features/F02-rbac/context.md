# F02 Роли и права — контекст
**Статус:** спроектировано · **Важность:** P0 · **Воркфлоу:** все · **Этап:** 1

## Зачем
Каждое действие в системе разрешается правом. Права галочками собираются в роли, роли выдаются сотрудникам (D-07).

## Важность для ключевых воркфлоу
Сквозное. Ошибка в правах = либо люди не могут работать (WF-2), либо видят чужие заявки, себестоимость, деньги (утечка).

## Реальные связи
| С чем | Что |
|---|---|
| Все экраны F13, F25, F24, F28, F29… | проверка прав на просмотр/изменение |
| F15 Агенты | агент — отдельный тип пользователя с ограниченной областью видимости |
| F16 Оператор | на старте — просто роль (A-14) |
| F14 Распределение | право «участвует в распределении» + направления (продукты) |
| F34 Журнал | изменение ролей и прав логируется |

## Возможные связи
- Доступ гидов/водителей (посадочные ведомости) — бэклог.
- Ограничение по направлениям (менеджер круизов не видит автобусы).

## Как я это понимаю
- Два уровня: **права на действие** (может ли редактировать тур) и **область данных** (какие заявки видит: свои / своего направления / все). Пользователь говорил только о галочках, но область видимости точно понадобится (менеджер vs агент vs руководитель) — заложу как отдельные права вида `orders.view.own|line|all`.
- Нужны пресеты ролей (Q-15) — соберём после разговора про агентов и менеджеров.
- Чувствительные права: видеть себестоимость/маржу, вносить ручные оплаты, менять цену туриста, удалять бронь, управлять ролями.
