# F13 Рабочее место продаж — контекст
**Статус:** спроектировано · **Важность:** P0 · **Воркфлоу:** WF-2, WF-5 · **Этап:** 1

## Зачем
Интерфейс, в котором менеджеры (и агенты — в своей панели) ведут заявки: очередь, карточка заказа, бронирование за клиента, места, оплаты, документы, звонки, чат.

## Важность
Основной инструмент 20 постоянных и 40+ сезонных менеджеров. Неудобство = медленная обработка = потерянные продажи.

## Реальные связи
| С чем | Что |
|---|---|
| F09 | работа с заказами |
| F14 | «мои заявки», новые назначения |
| F05/F04/F06 | бронирование мест, номеров, ручная цена |
| F10/F11 | ссылки на оплату, ручные оплаты, документы |
| F18/F19 | звонки и чат в карточке |
| F02 | что видно и что можно |
| F15 | агентская панель — тот же интерфейс с ограничениями (D-06) |
| F20/F21/F22/F23 | заявки на круизы, аренду, корпоратив, партнёрские туры |

## Как я это понимаю
- Одна кодовая база, две панели Filament: `/staff` и `/agent` (D-06). Различия в области видимости и правах — уточнить завтра (Q-02).
- Для сезонных сотрудников интерфейс должен быть понятен без обучения: очередь «что сделать сейчас», просрочки, напоминания.
- Пользователь хочет «разделить менеджеров и реально агентов» — значит, в отчётах/рейтинге они раздельно.
