# F01 Авторизация — контекст
**Статус:** спроектировано · **Важность:** P0 · **Воркфлоу:** WF-1, WF-2, WF-5 · **Этап:** 1

## Зачем
Вход в систему трёх типов пользователей: турист (без пароля, по коду), сотрудник, агент.

## Важность для ключевых воркфлоу
- WF-1: турист должен войти, чтобы оформить заказ/оплатить/доплатить. Сломан вход = нет онлайн-продаж и доплат.
- WF-2/WF-5: сотрудники и агенты не смогут работать.

## Реальные связи
| С чем | Что |
|---|---|
| F02 Права | после входа определяет, что пользователю доступно |

## Возможные связи
- Вход через MAX/VK ID, Госуслуги (не обсуждалось).
- Объединение дублей клиентов (один человек — телефон и почта).

## Как я это понимаю
- Турист: телефон → код по SMS **или** звонок (sms.ru, у пользователя есть аккаунт и API). Альтернатива — код на почту.
- Сотрудники и агенты — логин + пароль (агентам выдаётся по запросу). Для сотрудников стоит добавить 2FA позже.
- Риск: SMS стоят денег и их могут «качать» боты → лимиты по номеру/IP, капча, звонок-код дешевле SMS.
- Риск: клиент сначала оставил заявку с почтой, потом вошёл по телефону → нужно склеивать по совпадению контактов, иначе он не увидит заказ в ЛК.
- Сезонные менеджеры (40+): блокировка учётки одной кнопкой (A-12).
