# F20 Круизы — контекст
**Статус:** спроектировано · **Важность:** P1 · **Воркфлоу:** WF-6 · **Этап:** 1

## Зачем
Витрина речных круизов из API Инфофлот и Мостурфлот (D-13): теплоходы, каюты, цены, расписание; обновление раз в сутки ночью; на сайте — только заявка, менеджер бронирует вручную у круизной компании (D-12).

## Реальные связи
F07 (витрина в общей стилистике, `/rechnye-kruizy/`), F08 (SEO страниц круизов и теплоходов), F09 (заявка = заказ product_line=cruises), F14 (очередь «круизы»), F10 (оплата клиентом — вероятно, после подтверждения менеджером ⚠️), F11 (документы).

## Как я это понимаю
- Два поставщика с разными форматами → общая внутренняя модель (круиз, теплоход, каюта, цена) + адаптер на каждого.
- Цены/наличие на ночь могут устареть → заявка, а не покупка — это снимает риск.
- Своя наценка на круизы? Не обсуждалось ⚠️.
- Доступы к API пользователь даст.
