# Принятые решения

Формат: D-xx — решение. Источник/дата. Менять только с согласия пользователя.

- D-01 Пишем с нуля; старая платформа не используется и не интегрируется. (2026-10-19)
- D-02 Стек: Laravel + PostgreSQL + Redis + Filament + Next.js + Reverb + Meilisearch + Gotenberg. Принят по умолчанию под команду PHP+React, пользователь не возражал. (2026-10-19)
- D-03 Хостинг только в РФ (152-ФЗ, паспортные данные).
- D-04 Единое ядро заказов: один заказ, позиции разных типов, канал продажи и направление.
- D-05 Одно юрлицо: одна касса, один расчётный счёт для всех продуктов, включая аренду автобусов.
- D-06 Менеджер и агент — один интерфейс продаж, разные панели и область видимости.
- D-07 Права настраиваются галочками, из них собираются роли, роли выдаются сотрудникам.
- D-08 Выданные документы неизменяемы. Шаблоны версионируются. Загрузка PDF вместо сгенерированного = новая версия, старые хранятся.
- D-09 Штрафы, возвраты, аннуляции — только вручную. Никакой автоматики.
- D-10 Неоплаченные брони не снимаются автоматически — решает менеджер.
- D-11 Схемы оплаты: 30% + остаток за 30 дн; 15% + остаток за 14 дн (21, если праздник); 100%. Можно заявку без оплаты.
- D-12 Круизы, аренда автобусов, корпоратив — на старте только витрина и заявка.
- D-13 Круизы: Инфофлот + Мостурфлот по API, обновление раз в сутки ночью; теплоходы, каюты, цены.
- D-14 Партнёрские туры: заводятся вручную + позже API; своя наценка; клиент не видит, что тур партнёрский. Бронирование у партнёра сейчас вручную, цель — автомат.
- D-15 Отзывы — только после оплаты; модерация; ответ компании; фото и оценка.
- D-16 Распределение заявок по продуктам; рейтинг менеджеров по конверсии; лучшие получают чаще.
- D-17 Телефония — Манго Офис; звонок должен создавать заявку.
- D-18 Чат: на сайте + MAX. Другие мессенджеры — бэклог.
- D-19 Оплата — PayKeeper. Рассрочка — своя: учёт неоплативших, без банка.
- D-20 Мультивалютность закладываем в модель, но не включаем.
- D-21 Переносим только актуальные туры, их статистику и вес. URL сохраняем.
- D-22 Санатории — исключены полностью.
- D-23 ЕФИС «Электронная путёвка» не нужна.
- D-24 Деплой через GitHub Actions, инфраструктура через Terraform/API облака (нет SSH из среды Claude).
- D-25 Секреты — только в GitHub Secrets или настройках окружения, никогда в чате и в репозитории.
- D-26 Всю техническую часть делает Claude; пользователь — команды, доступы, тесты, решения.
- D-27 К первому запуску обязательны: промо-раздел (баннеры, бейджи) и конструктор главной (менять ссылки на категории).
- D-28 Цель — весь код за месяц непрерывной работы; переключение со старого сайта — зимой (низкий сезон).
- D-29 Основная ветка репозитория — `main`.
- D-30 Агентство — одна учётная запись. Регистрация по запросу с выдачей логина и пароля.
- D-31 Агент может всё, что менеджер, видит цену и свою комиссию.
- D-32 Бонусная система обсуждается в самом конце.
- D-33 Блог — отдельный функционал.
- D-34 В отелях есть всё: квоты, типы размещения, доп. место, подселение.
- D-35 Расходы тура: и при создании (план), и по факту выезда. Если группа не набралась — предлагают замену.
- D-36 Наличные и безнал вносятся в систему вручную.
