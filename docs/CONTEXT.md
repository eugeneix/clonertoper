# Контекст проекта

## Компания
- ООО «Туроператор Русь», сайт rtoperator.ru (старый, «древний», но приносит деньги).
- Одно юрлицо (D-05). Туры по России и СНГ, выездного туризма нет → ЕФИС ЭП не нужна (D-23).
- Сейчас работают на своей устаревшей платформе. Новую пишем с нуля (D-01).

## Цифры (на 2026-10)
- 780 туров в каталоге; >150 заявок в месяц; >20 агентов; ≈300 сотрудников всего.
- Продажи: ≈20 постоянных менеджеров + 40+ сезонных (part-time). Система не должна ограничивать число пользователей.
- Трафик: ~60% из поиска и рекламы → SEO и сохранение URL критичны (F08).
- Текущие URL туров: `/tury/poekhali/<slug>-<id>/`, категории `/tury/<slug>/`, круизы `/rechnye-kruizy/`,
  корпоратив `/korporativnye-tury/`, аренда `/arenda-avtobusov/`, ЛК `/lk/`, отзывы `/feedback/`.
- Чат на текущем сайте с 08:00 до 22:00, мессенджер MAX.

## Продукты
1. Свои туры — основной продукт: многодневные, однодневные, выходного дня, фестивали, праздничные; с автобусом и без.
2. Партнёрские туры — перепродажа, своя наценка, клиент не видит, что тур партнёрский (D-14).
3. Круизы — Инфофлот, Мостурфлот, только витрина + заявка (D-12, D-13).
4. Аренда автобусов — свой парк (меняется), витрина + заявка.
5. Корпоратив — отдельный канал/воронка поверх всех продуктов, заявка → КП → договор → счёт → акт.
6. ~~Санатории~~ — исключены (D-22).

- **WF-8** Послепродажа (документы, поездка, отзыв).

## Допущения (A-xx). ⚠️ = не подтверждено пользователем
- A-01 Цена за человека. Суммы хранятся с кодом валюты; пока только RUB (D-20).
- A-02 Схемы оплаты — справочник, выбирается в туре: А 30% + остаток за 30 дн; Б 15% + остаток за 14 дн (21, если начало тура праздничное); В 100%.
- A-03 ⚠️ «Праздничный» = дата начала тура попадает на праздник по производственному календарю ИЛИ тур вручную отмечен праздничным.
- A-04 ⚠️ Если до тура меньше срока доплаты — требуем 100%, менеджер может изменить.
- A-05 Можно оставить заявку без оплаты. Неоплаченные брони система НЕ снимает, только подсвечивает (D-10).
- A-06 Штрафы, возвраты, аннуляции система не считает, только фиксирует ручные действия с автором/временем (D-09).
- A-07 Детские скидки, наценки, доп. услуги — задаются в каждом туре вручную; менеджер может вручную менять цену туриста (в журнал).
- A-08 ⚠️ «Рейсы стекуются»: рейс (автобус+схема) и выезд тура — разные сущности, связь многие-ко-многим. КРИТИЧНО для модели данных, подтвердить на примере.
- A-09 У тура может не быть автобуса (однодневные, «любой транспорт») — тогда нет выбора места.
- A-10 Подселение — флаг в заявке, пару подбирает менеджер.
- A-11 Распределение по очередям продуктов; чаще получает тот, у кого выше конверсия. Формула — Q-05.
- A-12 Сотрудника (в т.ч. сезонного) можно отключить одной кнопкой, его заявки переходят другим.
- A-13 Агент и менеджер — один интерфейс продаж, разные панели и видимость (D-06). Детали — Q-02.
- A-14 Кабинет оператора на старте = роль из прав (Q-01).
- A-15 Круизы, аренда, корпоратив — витрина + заявка, бронируют вручную.
- A-16 ⚠️ У MAX есть API ботов для бизнеса, подходящее для единого окна чата — проверить до разработки.
- A-17 ⚠️ Если выгрузки туров не будет — парсим открытые страницы сайта (только текст/фото), цены и даты грузим отдельно.
- A-18 ⚠️ «Старая статистика» = продажи/просмотры по турам для отчётов.
- A-19 Бейджи: ручные (со сроками) и автоматические (остаток мест, скидка).
- A-20 Подборки — вручную или по правилу (тег, период), со своей SEO-страницей.
- A-21 Нужен производственный календарь РФ (праздники) — для схем оплаты (A-03).
